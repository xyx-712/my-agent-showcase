# PDF 摘要与来源编号修复（2026-11-23）

## 根因

代码可复现的缺陷：answer_documents 传给模型的 sources 包含原始 chunk.index，却不明确提供本批引用 source 编号；后端按本批 sources 数组0起始下标校验，跨批次或模型按1起始编号时容易错配。不能凭截图确定用户那次模型的原始输出，本次没有读取个人PDF或调取个人任务内容。

摘要缩写此前直接走通用检索/分批问答，没有定位“摘要”范围，且可能把摘录当缩写。错误提示又统一要求“补充明确资料”，混淆模型错误与资料不足。

## 修改

- skills.py：回答模型输入删除原始index，每批显式source；严格参数和逐字引文校验保持。越界或编号与引文不符时，仅通过当前批次内唯一原文匹配纠正；重复/无匹配拒绝。负数、错误类型按原严格schema拒绝。不按加减编号猜测。
- abstracts.py：定位显式中文/英文摘要标题，保留原文件、页码和行位置，跨块收集到关键词/引言/下一明确标题。普通“摘要第几行”不误作新标题。无标题或无正文追问，多候选要求编号选择。
- document_agent.py：摘要范围与选择持久化；错误分为无摘要、多个候选、模型格式/引用错误、连接/工具错误。每次最多两次模型格式尝试，保留成功批次，失败批次不推进offset。旧未定位摘要的任务首次继续清理旧不适用输出，重新定位；新定位的有效批次重启后复用。
- 缩写正文用synthesis，证据单独逐字校验，输出不重复整段摘录。事实与推断标签保留，原文仍可点击查看。
- advanced_evaluation.py：修复测试初始化顺序，先设置临时数据库再导入skills/API；断言前关闭checkpoint以避免Windows失败清理掩盖原始断言。

安全边界：候选资料来自当前服务端身份及任务范围，错误编号不能扩大到其他文件/身份。资料中的指令不会授权工具。没有修改上传接口、身份机制或放宽文件边界。

## 复现

停止原后端，在原终端按README原命令重新启动新代码，不需清库或重新安装依赖。前端启动方法不变。上传自己的PDF前，可先运行：

```powershell
cd <LOCAL_PROJECT_PATH>
.\.venv\Scripts\python.exe -X utf8 -m tests.abstract_evaluation
.\.venv\Scripts\python.exe -X utf8 -m tests.abstract_evaluation --ollama
```

后一个命令要求Ollama已运行、qwen2.5:7b已安装，自动生成并上传虚构PDF到临时测试服务。手动界面上传含摘要标题的文字PDF，发送“将文件中的摘要部分，为我缩减一些”，查看正文和原文引用。旧失败任务可直接发送“继续任务”；如资料发生变化，按提示重新检索。多个摘要回复“选择摘要 1”。
