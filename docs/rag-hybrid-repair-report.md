# RAG最小混合召回修复报告

2026-11-25。仅独立展示副本；两个业务文件修改，未改切分、配置、索引结构、已有数据或许可证。没有重建/迁移/恢复已有索引。测试仅新建临时SQLite/Chroma及虚构TXT；临时测试进程退出后清理自己的临时目录，不操作用户数据。使用现有独立Python虚拟环境解释器，不复制其项目源码或下载模型。

## 根因与修改

1. 历史5/10仅是0.65门槛过滤后的正确来源保留率，不能当作最终回答率；原始向量候选已有正确证据。
2. qa.py此前整批无语义达标时才启用词法证据。一份达标会阻止另一份低分必要来源的词法复核。现改成逐候选独立接纳，仍保留原模型答案充分性与引文验证。
3. service.py此前词法只能复核向量Top-K。现在对同一用户授权、READY且模型/维度/代次可用的原文派生片段进行独立关键词匹配；每请求最多检查5000片段，最多8个词法候选，与原有向量Top-K合并按chunk_id去重。语义Top-K默认为4，合并后最多12项，并非最终证据必有12项。
4. 向量候选原分数不变。新增词法候选用相同模型的真实文档向量与查询向量计算余弦，不写回或更新索引，不制造高分。增加模型摘要复核与最终归属/代次复查。词法仍要求两项不重叠有效词，答案必须有原文支持。

## 剩余问题与边界

真实模型对“谁有权恢复数据，需要检查什么”“设置登录密码有什么要求”“发现异常登录如何处理”在正确证据已被接纳后仍输出无依据，最终无引用。边界位于现有answer_documents/模型输出的答案充分性链路，不能从现有记录进一步断言具体提示词缺陷。本次未改该模块，也没有为了提高数值绕过校验。如需继续修复，须单独批准调查/修改 src/agent/skills.py 或提示模板，并记录模型原始结构化输出后再定位。

独立关键词召回仍是双字词启发式，不能解决完全同义改写；扫描/候选上限可能漏证据，词法并列按稳定ID排序并非语义重排。新增词法候选可能额外Embedding调用及更多回答上下文，服务故障仍显式报错，不伪造分数。小样本拒答通过不等于全面安全认证。没有新增模型、依赖、前端或数据库变更；未提交/推送/部署。
